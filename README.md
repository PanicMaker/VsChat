在 VSCode 侧边栏中通过微信或 QQ 直接聊天。微信通道基于腾讯 [OpenClaw iLink 协议](https://github.com/Tencent/openclaw-weixin)，QQ 通道基于官方 [QQ Bot API v2](https://bot.q.qq.com/wiki/develop/api-v2/)。两个通道共用聊天界面，但凭据、连接和历史记录彼此隔离。

> 多行草稿、发送恢复、多窗口同步、未读提醒、历史搜索与发送快捷键设置为当前工作区新增能力；第四批补充 Markdown、代码复制和有序多附件接收，第五批增加普通文件发送与另存为，第六批增加导出、备份恢复和容量管理，第七批增加显式收件人选择及按联系人隔离的历史、草稿和未读，第八批补充连接健康、恢复游标保护、长历史性能优化和 CI 回归门槛，均尚未发布新版本。

## ✨ 功能特性

- 🔀 **双通道** — 可在 `wechat` 与 `qq` 之间切换，原微信方案保持可用
- 🔐 **微信扫码登录** — 微信通道在 VSCode 中扫描二维码登录
- 🤖 **QQ Bot 登录** — 使用 AppID/AppSecret 获取 Access Token，密钥保存在 VS Code SecretStorage
- 🔌 **QQ 实时事件** — Gateway WebSocket 心跳、Session 恢复和断线退避重连
- **连接健康** — 独立显示连接中、在线、恢复中、离线或需处理的错误，以及最近确认和预计重试时间；状态变化保留当前联系人、草稿和未读。
- 💬 **实时消息收发** — 长轮询接收消息，即时发送文本
- 🖼️ **图片支持** — 微信使用 AES-128-ECB 媒体链路；QQ 使用官方分片上传接口
- 在聊天输入框按 **Ctrl+V / ⌘V** 粘贴截图或复制的图片，确认缩略图后使用当前发送快捷键或点击发送；点 × 可取消。每次发送一张（最大 10 MB），已有文字保留为草稿。文件由扩展宿主处理；Remote SSH 的实际剪贴板与路径行为仍需人工验收。
- 自己发出的图片也会显示缩略图，可点击放大；QQ 和微信均会保存发送图片，重载后仍可查看。旧记录若没有保存图片文件，则仍显示占位文字。
- ↩️ **引用回复** — 微信保留原引用逻辑；QQ 使用 `msg_id` 与 `message_reference`
- 🔍 **图片预览** — 点击接收的图片在 Lightbox 中全屏查看
- 💾 **消息持久化** — 基于 SQLite 的本地消息存储，重启后保留历史
- **明确收件人与多联系人** — 先在“发送给”中选择联系人，按当前机器人账号与联系人隔离聊天；新来信不改变发送对象。上传、重试和发送回执始终归属原收件人。
- 📜 **历史分页** — 所选联系人首次加载最近 100 条，点击聊天顶部“加载更早消息”继续查看；也可选择“全部历史（只读）”查看当前通道的旧记录
- **长历史展示优化** — 普通旧页前插保留已显示的消息节点与阅读锚点；图片延迟加载、异步解码，宿主限制媒体读取并发和展示缓存保留量。
- **多行草稿与发送恢复** — 默认 Enter 发送、Shift+Enter 换行，可设置 Ctrl/Cmd+Enter 发送；文字、引用、图片、文件草稿和发送状态按通道、机器人账号及联系人分别保存。发送中显示进度并防止重复点击，确认成功后才清除对应草稿。
- **历史搜索与上下文** — 搜索所选联系人全部本地记录，可组合关键词、日期和类型筛选；分页、上下文与引用定位遵循相同会话范围。“全部历史（只读）”另提供当前通道的跨联系人历史查看。
- **Markdown 与代码复制** — Chat 和独立消息上下文支持 Markdown 排版及代码块复制，可通过设置实时切换；Output / Changes 中的消息文字保持原文显示。
- **有序多内容消息** — 同一条收到的消息可保留正文和多个附件，显示图片、语音转写、文件名及协议提供的大小等信息；微信图片按内容项分别缓存。
- **文件发送与另存为** — 微信与 QQ 均可选择单个普通文件，预览名称与大小后明确发送；收到的可用文件可另存为，微信文件会先解密并校验。单文件上限为本插件设定的 20 MiB。
- **数据管理** — 按日期导出 Markdown/JSON，备份当前通道历史及可选的本地图片缓存；预览后追加恢复，查看分类容量，将符合条件的旧图片缓存移入保留目录。
- **阅读位置与新消息提示** — 接近底部时跟随新消息；查看历史时保留阅读位置并显示“有 N 条新消息”，点击可回到最新消息。
- **多窗口历史同步** — 共用同一通道数据库的窗口自动补充新增消息和同步清空结果；窗口聚焦或面板重新显示时补同步，已加载的历史保持可读。
- **共享未读与快捷打开** — 联系人分别维护已读进度，状态栏汇总当前机器人账号的未读数；读完一个联系人不会清除其他人的未读。通知可打开对应联系人，共享窗口同步同一会话的已读进度。
- 🔄 **会话恢复** — 尝试恢复有效登录会话；登录失效时需重新登录
- 🌐 **代理支持** — 可配置 HTTP 代理
- 📱 **Bark iPhone 推送** — 收到新消息时推送提醒到 iPhone，不再错过
- 🔄 **自动更新** — 基于 GitHub Release 检测新版本，一键下载安装

### 📱 iPhone 推送提醒（Bark）

1. iPhone 安装 [Bark](https://apps.apple.com/cn/app/bark-%E6%8E%A8%E9%80%81/id1403753865) 并获取设备 Key。
2. 在 VSCode 设置中配置 `vschat.barkUrl`，例如 `https://api.day.app/你的Key/`。
3. 执行命令 **VsChat: Test Push Notification** 验证手机能否收到通知。
4. 之后每条收到的微信或 QQ 消息都会触发 iPhone 通知。也支持带 `{title}` / `{message}` 占位符的完整 URL 模板，用于自定义提示音、分组等参数。

> 注意：推送依赖扩展运行，VSCode 窗口需要保持连接。消息内容超过 500 字符时会截断。

## 🐧 QQ Bot 接入

### 1. 创建机器人并开通事件

1. 前往 [QQ 开放平台](https://q.qq.com/#/) 创建机器人，取得 `AppID` 和 `AppSecret`。
2. 在机器人后台开通单聊能力，并申请/启用 `GROUP_AND_C2C_EVENT` 事件权限；插件只订阅该项（`1 << 25`），用于接收 `C2C_MESSAGE_CREATE`。
3. 发布或配置机器人测试环境，并在 QQ 中添加/使用机器人。具体后台选项以 [QQ Bot API v2 启动接入](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/getting-started.html) 为准。

> QQ 官方已弃用旧 Token 鉴权。本插件按当前文档使用 AppID/AppSecret 请求 `access_token`，并在到期前自动刷新；OpenAPI 与 Gateway 鉴权均使用 `QQBot ACCESS_TOKEN`。

### 2. 在 VSCode 中配置

1. 打开命令面板，执行 **VsChat: Configure QQ Bot**。
2. 输入 AppID 和 AppSecret。AppSecret 不写入 `settings.json`，而是保存到 VS Code SecretStorage。
3. 选择提示中的 **Reload Window**。命令会把 `vschat.channel` 切换为 `qq`。
4. 重载后插件会自动连接 Gateway。首次使用时，请先从 QQ 给机器人发送一条消息，插件会从事件中记录该用户的 `user_openid`；随后在侧边栏的“发送给”中明确选择该联系人。

也可以通过扩展宿主环境变量 `VSCHAT_QQ_APP_ID`、`VSCHAT_QQ_APP_SECRET` 提供凭据。`vschat.qqUserOpenId` 仅增加一个配置候选，不会自动选中或覆盖已选收件人；该对象没有可用被动回复额度时仍不能从界面发送。填写 OpenID 不代表获得主动发送权限。

### QQ 通道实现范围与平台规则

- 支持单聊文本、图片及单个普通文件发送，以及文本、图片、语音转写和文件事件展示；可用的收到文件支持另存为。
- QQ 原生表情标签会读取 `ext` 中的 Base64 描述并显示为 `[表情名]`（例如 `[白眼]`）；无法解码时回退为 `[QQ表情 #faceId]`，启动 QQ 通道时也会自动修正历史消息中的同类标签。
- 图片和普通文件按官方流程执行 `upload_prepare` → 预签名 URL 分片 PUT → `upload_part_finish` → `/files` 合并 → `msg_type=7` 发送；普通文件使用 `file_type=4`。
- 相同 QQ 消息可能重复推送，插件在账号及联系人范围内按事件消息 ID 去重；事件处理成功后，将 Gateway 序列号、Session ID 与凭据身份作为同一个恢复检查点原子保存。处理或保存失败不会把恢复位置推进到失败事件之后。
- 多窗口共用同一数据库时，QQ 被动回复序号按 AppID、用户 OpenID 和入站消息 ID 独立持久化，在跨进程锁内原子分配；普通文本、引用、图片和文件共用计数，引用切换、重载窗口及清空聊天记录都不会把序号重置为 `1`。发送失败也不会回收已分配的序号，避免网络超时后重用已被 QQ 接受的序号。
- 入站消息的去重、落库和上下文更新在同一锁内完成；延迟或重复事件不会回退最近上下文。用户选定联系人后，发送、上传、配额预留及历史记录统一使用固定的 AppID 与 OpenID，新来信不会改投。
- 当前界面只在所选联系人有可用被动回复额度时允许发送：插件按 60 分钟、每条入站消息最多 4 次管理，所有窗口共用。额度过期或被其他窗口耗尽时停止发送，不自动转为主动消息。官方发送文档概要写 60 分钟，而同页 `msg_id` 字段仍写 5 分钟，存在不一致；平台实际拒绝会作为发送错误呈现，不能保证整个窗口都可送达。[QQ 单聊发送文档](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_users_user_openid_messages.post.html)
- 联系人按当前 AppID 隔离，OpenID 不能跨机器人复用。更换 AppID、AppSecret 或移除凭据会使已有发送快照失效；旧连接收到的消息仍归属原机器人账号。配置候选和导入历史都不能建立被动回复额度。

### 切回微信

将 `vschat.channel` 改为 `wechat` 并重载 VSCode。微信历史仍保存在原数据库中，QQ 历史使用独立的 `vschat_qq_chats.db`，切换不会覆盖另一通道的数据。

### 历史记录与 Remote SSH

多个扩展宿主共用同一聊天库时，读写会通过跨进程文件锁串行执行，每次操作读取最新数据库，保存采用临时文件原子替换。关闭窗口不再回写旧内存快照；首次写入已有数据库前会保留一份 `.db.bak` 备份。

扩展启动后即维护历史同步与状态栏未读数，无需先打开聊天面板。当前窗口的收发事件会触发刷新；其他窗口的写入通过约每 1.5 秒一次的数据库文件变更检查发现，仅检测到变化或请求补同步时才读取数据库。普通新增消息按增量追加；清空历史时同步重置各窗口视图，避免迟到的历史页把已删除消息带回来。窗口聚焦、聊天面板重新显示时会主动补同步。

同步仅覆盖**共用同一存储目录、同一通道数据库**的窗口；不同机器、不同 VS Code 配置文件或其他独立数据库之间不交换消息和已读进度。所有写入同一数据库的窗口都应升级并重载。当前选择与草稿属于各自窗口；草稿按通道、机器人账号及联系人隔离，不参与跨窗口同步。

“清空聊天记录”会清除当前通道全部联系人及旧账号的消息与未读数，不受当前收件人选择影响，并同步到共享窗口，同时保留图片文件。第六批可在“数据”面板预览超过 7 天且无历史引用的图片缓存，确认后移入 `cache-quarantine` 保留目录；该操作不删除文件，也不会释放磁盘空间。

Remote SSH 的数据库位于远程主机的 `~/.vscode-server/data/User/globalStorage/panicmaker.vschat/`。升级后需关闭或重载所有使用 VsChat 的旧扩展宿主，让每个窗口都运行修复版；旧版进程不会遵守新的文件锁。已被旧版覆盖、且没有备份的消息无法从不含正文的诊断日志完整恢复。

升级到 `0.9.3` 后，请重载所有使用 VsChat 的窗口（Remote SSH 需要在远程环境安装），再从 QQ 给机器人发送一条新消息。旧版本只有一组可能被重置的回复计数，无法可靠恢复每条消息已使用的序号；首次升级会保守停用升级前的回复上下文，但保留聊天正文。多窗口修复适用于共用同一个远程/本地存储目录的扩展宿主，不协调不同机器或不同 VS Code 用户数据目录中的独立实例。

### 🔄 自动更新（基于 GitHub Release）

现有 GitHub Actions 工作流在向 `main`/`master` 推送时构建 `vschat.vsix` 并发布为 `v{版本号}` 的 Release。第八批在构建任务中加入 `npm test`，发布任务通过 `needs: build` 等待测试、构建和打包成功；原有发布触发条件保持不变。本轮只做本地验证，没有触发托管 Actions 或真实发布。插件在此基础上实现自更新：

1. 启动后 10 秒自动检查一次，之后每 6 小时检查一次；也可随时执行 **VsChat: Check for Updates** 手动检查。
2. 发现新版本时弹出提示，确认后下载 VSIX 并自动安装，重载窗口即可生效。
3. 发布新版本前，记得先修改 `package.json` 中的 `version`，推送后等待 workflow 生成 Release（几分钟），插件下次检查即可发现。

可用 `vschat.autoUpdate` 设置（默认 `true`）关闭自动检查。注意：

- GitHub API 匿名访问有每小时 60 次的限制，检查失败会自动跳过，不影响插件使用。
- 第一次安装仍需要手动安装 VSIX，之后同一台机器上的更新即可自动完成。
- 若自动安装失败，会提示打开 Release 页面手动下载。

|------|------|------|
| **入口** | `extension.ts` | 扩展激活/停用，初始化 DB 和客户端，注册命令 |
| **客户端接口** | `chat-client.ts` | 为 Webview 统一微信与 QQ 的连接、事件和发送能力 |
| **收件人类型** | `recipient-types.ts` | 账号与联系人共同标识会话，发送快照仅供宿主使用 |
| **微信客户端** | `wx-client.ts` | QR 码登录、长轮询消息、文本/图片/文件发送、AES 加解密、CDN 文件上传 |
| **微信协议类型** | `wx-types.ts` | iLink 消息、二维码登录、轮询和发送响应结构 |
| **QQ 客户端** | `qq-bot-client.ts` | Access Token 刷新、Gateway 心跳/恢复、C2C 消息、富媒体分片上传 |
| **视图桥接** | `chat-view-provider.ts` | 管理 Webview 生命周期、共享历史同步、状态栏未读提醒、历史查询和发送结果反馈 |
| **历史展示准备** | `history-presentation.ts` | 限制媒体读取并发，缓存图片展示数据与 Markdown 解析结果，图片缓存随数据版本失效 |
| **Markdown 解析** | `markdown-content.ts` | 将消息文本解析为受限显示节点，过滤外部链接，保留原始 HTML 与内嵌图片的文字表示 |
| **文件操作** | `file-actions.ts` | 原生选择和保存对话框、宿主中的文件快照草稿、按消息及内容项定位附件 |
| **文件传输** | `file-transfer.ts` | 文件名处理、下载地址与重定向校验、大小及超时限制、微信文件解密和完整性检查 |
| **数据管理** | `archive-actions.ts`、`chat-archive.ts` | 分享导出、备份格式校验、恢复预览与明确确认；不导出原始数据库或登录状态 |
| **存储维护** | `storage-maintenance.ts` | 按消息引用收集与恢复图片缓存、分类容量统计、旧无引用缓存移入保留目录 |
| **数据库** | `chat-db.ts` | 基于 `sql.js` 的 SQLite 存储，管理消息与共享已读进度，提供历史查询、稳定归档标识及追加恢复 |
| **通用类型** | `types.ts` | 定义 `ChatMessage`、`ReplyTo`、`WebViewInbound/Outbound` 等跨通道接口 |
| **前端** | `webview/` | 聊天 UI：消息气泡、图片预览、输入栏、登录屏 |

### 数据流

1. **通道选择**：`extension.ts` 读取 `vschat.channel`，创建微信或 QQ 客户端，并使用各自独立的消息数据库。
2. **微信登录/收发**：保留原扫码、`getupdates` 长轮询、iLink `sendmessage` 与加密媒体链路。
3. **QQ 登录/接收**：AppID/AppSecret → Access Token → `/gateway` → Identify/Resume → `C2C_MESSAGE_CREATE` → 本地 DB → Webview。
4. **QQ 发送文本**：Webview 提交已选收件人 → 宿主校验选择、固定账号与联系人 → 预留该联系人的被动回复序号 → `/v2/users/{user_openid}/messages`。
5. **QQ 发送图片**：Webview → 临时文件 → QQ 分片上传/合并 → `msg_type=7` 消息。
6. **窗口同步与已读**：数据库变化 → 读取所选会话增量及各联系人未读数 → 更新面板和状态栏；有焦点的可见面板读到最新 → 推进该会话已读进度 → 其他共享窗口刷新。
7. **发送普通文件**：原生文件选择 → 宿主保存文件快照并返回草稿标识 → 用户明确发送 → 通道上传并发送单个文件消息 → 确认平台回执后落库。
8. **附件另存为**：Webview 提交消息 ID、内容项索引及历史代次 → 宿主读取已存下载信息 → 用户选择保存位置 → 下载、解密及校验完成后写入；密钥和文件下载地址不传入 Webview。
9. **备份恢复**：读取当前通道备份并校验 → 显示可追加、重复及冲突数量 → 用户确认 → 原子追加消息 → 按新消息 ID 恢复图片缓存，并分别报告消息与图片结果。

## 📖 使用方式

1. 安装扩展后，VSCode 活动栏出现 💬 **VsChat** 图标
2. 微信通道：打开聊天面板，执行 `VsChat: Login`，再用微信扫描二维码
3. QQ 通道：先执行 `VsChat: Configure QQ Bot`，按提示重载并从 QQ 给机器人发一条消息
4. 连接成功后，在 **发送给** 中明确选择联系人；没有可发送对象时，让对方先给当前机器人发送一条私聊消息。查看旧记录可选 **全部历史（只读）**
5. 检查收件人后在输入框中输入文字，默认 Enter 发送、Shift+Enter 换行；可在设置中改用 Ctrl/Cmd+Enter。点击 📎 选择图片或粘贴截图；发送普通文件请点击 **文件**。检查草稿后再按发送

### 收件人与会话范围（第七批）

每次先在 **发送给** 中选择对象。列表以联系人 ID 显示，来源于本地已有私聊、当前账号的只读历史及 QQ 配置候选；它不是好友昵称目录，不查询全部好友，也不提供群聊。新消息只更新对应联系人的消息与未读，不自动改变发送目标。各窗口可选择不同联系人。

聊天、历史分页、搜索、上下文和引用均按 **当前机器人账号 + 联系人** 隔离。切换对象时保留各自的草稿与阅读位置；迟到的历史响应、文件选择结果或发送回执不会写到另一人的会话。阅读位置仅在重新同步的消息范围内恢复，更早的位置需重新加载历史。**全部历史（只读）** 可查看当前通道所有联系人及旧账号记录，不允许发送，也不推进任何联系人的已读进度。导入的历史只提供查看，不会激活收件人路由或 QQ 回复额度，也不提供引用发送按钮。

微信需要本次登录收到的真实消息确认机器人账号、联系人与对应会话信息；同一有效登录恢复时可复用其绑定记录，换登录不会继承其他登录的发送路由。`getupdates` 的轮询游标只用于继续拉取消息，不是发送用的 `context_token`。平台返回 `-14` 时按登录失效处理，停止发送并提示重新登录，不再去掉 token 重试。

QQ 仅展示当前 AppID 的联系人和配置候选，界面是否可发取决于该对象当前可用的被动回复额度。`vschat.qqUserOpenId` 不隐式覆盖用户选择，也不保证主动发送权限。微信旧 `vschat.fromUserId` 设置仅保留兼容用途，新界面仍需选择由当前登录真实来信建立的对象。

发送开始时固定账号与收件人，后续上传或重试不改投；凭据或登录变化会停止未完成的发送准备。需要重试时回到原联系人的草稿操作，未知送达结果仍需先由用户核实。

### 连接健康与恢复（第八批）

面板通过独立连接状态栏显示离线、连接中、在线、恢复中和错误。QQ 显示最近心跳确认，微信显示最近成功轮询响应；安排重试时显示预计重试时间。更新连接状态不会替换当前联系人、清除草稿或推进未读，也不代表消息已送达或已读。认证或权限错误需要按提示重新登录、检查机器人配置或重新连接。

QQ 为心跳 ACK 设置超时；心跳请求、ACK、重连和会话失效等控制帧不排在消息处理队列之后。普通事件串行处理，队列最多保留 256 个事件、8 MiB 载荷，单个载荷最多 1 MiB；连接准备和单事件处理均设 30 秒超时。积压、处理失败或超时会断开并从已保存检查点恢复，不把未处理事件的序列号当作恢复位置。临时断线按退避策略重连，明确的不可恢复关闭码显示错误并停止循环重连；旧连接晚到的响应不能推进新连接的状态或检查点。

已进入原子数据库写入的操作不能强行取消。QQ 会等待旧处理结束后再重连，避免留下并行写入的处理任务；若底层存储永久卡住，状态会停留在等待处理，需要排查存储并重载窗口。

微信停止后立即重启时，新轮询会等待旧轮次结束，避免两个轮询并行提交游标。轮询请求超时为 45 秒，入站图片下载超时为 30 秒；停止会取消请求、退避等待和正在处理的媒体。只有整个消息批次保存成功后才提交游标，失败批次继续从旧位置请求并去重；暂时网络或存储错误显示“恢复中”，`-14` 或 HTTP 401 显示登录失效并要求重新扫码。

微信恢复游标按登录凭据隔离，同一凭据重启可继续使用。**首次升级第八批时，不复用无法确认账号归属的旧全局游标**，而是从空游标重新请求服务端可返回的消息，再按已有消息标识去重。这不会补回服务端已不再提供的历史；换登录也不会继承另一登录的接收位置或发送路由。

### 草稿与发送结果

文字发送成功后才清空文字和引用；图片或文件发送成功后只清空对应附件，已有文字和引用仍是独立草稿。发送期间暂时锁定输入，避免重复提交。多行正文按原换行显示，输入法确认候选词不会触发发送。

失败时保留草稿并提供手动重试。网络异常、微信未返回明确回执等情况会显示“发送结果待确认”：请先检查聊天记录或收件端，确实需要时再点击“确认可能重复，重新发送”；如果对方已收到，可点击“已确认对方收到”。插件不会自动重发。这里的“已发送”是发送接口正常完成，不代表对方已读。

重开面板后，未完成的发送会先查询本次扩展运行中保存的结果；若扩展也已重启、无法核实结果，则保留草稿并显示“待确认”。这不是持久化发送队列。文字、引用、图片、文件草稿及发送回执按通道、机器人账号与联系人隔离，使用 VS Code Webview 状态保存，不跨窗口同步；文件内容快照仍只在当前扩展宿主中有效。

升级前未绑定联系人的旧草稿保留在 **全部历史（只读）** 中供查看与手动复制，不会自动分配给最近联系人，也不能直接重试发送。确认收件人后，可手动把需要的文字复制到该联系人的新草稿；文件需重新选择。

### 发送快捷键

在 VS Code 设置中修改 `vschat.sendShortcut`：`enter`（默认）为 Enter 发送、Shift+Enter 换行；`ctrlEnter` 为 Ctrl+Enter 或 Cmd+Enter 发送、Enter 换行。修改立即生效，无需重载，输入框提示会同步更新，已有草稿保留。

两种模式下，输入法组合输入及带 Shift 或 Alt 的 Enter 都不会发送；默认 `enter` 模式下，Ctrl/Cmd+Enter 也不会发送。也可以点击发送按钮提交草稿。

### Markdown 与代码复制（第四批）

`vschat.renderMarkdown` 默认开启，Chat 模式和独立消息上下文可显示标题、列表、引用、表格、链接、行内代码及代码块等 Markdown 内容。点击代码块旁的 **复制代码** 可复制代码正文；复制失败时提供重试提示。关闭设置后显示原文，设置修改立即生效，无需重载。Output / Changes 模式中的消息文字始终以纯文本展示。

原始 HTML 只作为文字显示，不执行脚本或嵌入网页；Markdown 中的图片语法显示替代说明，不加载其中的图片地址。正常收到的图片附件仍按通道的图片规则展示。链接只允许受支持的 HTTP、HTTPS 或邮件地址，需点击后打开；无法解析或过长的消息回退为纯文本。

### 多内容消息与附件（第四批）

微信按消息中的内容项顺序保存，QQ 保留正文以及附件列表顺序。同一条消息可包含文字、图片、语音转写、文件和视频；附件名称、链接、大小和 MIME 类型在协议提供时一并保留。文件和视频显示附件卡片；第五批将文件卡片改为按能力提供“另存为”，视频仍可点击有效链接打开。搜索仍匹配已保存的正文摘要，类型筛选也会匹配混合消息中的内容项。

微信先保存完整消息，再逐项下载、解密和缓存图片；某一项下载或缓存失败不会丢弃已保存的文字或其他附件。微信图片缓存按消息及内容项区分，重开历史时分别加载。QQ 收到的图片仍使用远程链接，尚未增加本地下载缓存，链接失效或离线时可能无法显示；原有发送图片缓存仍可读取。

第四批的范围是接收、存储与显示；当时未提供的普通文件发送和文件解密另存为已在下述第五批补充。仍不支持一次发送多个附件，升级也不会补回旧版本已经漏存的附件。

### 文件发送与另存为（第五批）

点击输入栏的 **文件**，在 VS Code 原生对话框中选择一个非空普通文件。宿主会保存所选内容的快照，输入栏显示文件名与大小；选择操作不会上传或发送，之后需使用发送按钮或当前发送快捷键明确提交。文件和图片草稿互斥，文字与引用保留为独立草稿，不会作为文件说明或引用一并发送。发送前可点草稿旁的 × 移除文件；取消选择对话框会保留已有草稿。

微信和 QQ 均支持单个普通文件发送，**发送与下载的单文件上限均为 20 MiB（20 × 1024 × 1024 字节），这是本插件的应用限制，不是平台上限**。文件沿用发送结果提示：明确的上传失败可手动重试，最终消息请求的结果不明或平台未返回消息 ID 时保持“待确认”，不会自动重发。面板恢复时会检查文件草稿是否仍在当前宿主中；宿主重启后需要重新选择文件，不支持跨重启继续上传。

文件卡片会显示能否保存及不可用原因。点击 **另存为…** 后，通过原生对话框选择位置；取消对话框不会下载或写入文件。下载期间可点击 **取消保存** 请求中止，以最终状态为准；已经开始的目标文件写入不能通过此按钮撤销。界面显示保存中、成功、失败或取消结果，失败后可手动重试保存；下载及校验完成前不会写入目标文件，保存后不会自动打开或执行它。

| 文件来源 | 当前另存为能力 |
|---|---|
| 微信收到的文件 | 已保存有效媒体引用与密钥时，下载并解密；协议提供大小或 MD5 时进行校验。 |
| 微信旧历史 | 若旧 JSON 已包含完整下载信息，可兼容读取；缺少密钥或引用时显示不可用，无法恢复当时未保存的数据。 |
| 微信发出的文件 | 确认发送后保留媒体引用，可在引用仍有效时另存为。 |
| QQ 收到的文件 | 有受支持且未失效的下载地址时可另存为。 |
| QQ 发出的文件 | 平台普通文件上传响应不返回下载 URL，当前也未缓存发送文件，卡片暂不能另存为。[QQ 单聊上传文档](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_users_user_openid_files.post.html) |

下载仅接受 HTTPS 的 `qq.com`、`qq.com.cn`、`qpic.cn`、`gtimg.cn` 域名及其子域名，每次重定向都会重新校验。下载使用 30 秒总超时，并按实际读取字节限制大小；微信解密后也检查明文大小。文件下载地址与解密信息由宿主读取，不发给 Webview，下载请求不附带聊天凭据。聊天数据库仍使用现有明文存储方式，这不等同于存储加密。

本批没有多文件一起发送、视频下载、自动打开文件、文件缓存管理或断点续传。真实微信／QQ 文件收发、原生文件对话框、保存权限与 Remote SSH 的路径行为仍需手工集成验收；源码实现与模拟测试不代表这些场景已经验收，本轮未发送真实消息或发布。

协议实现参考：[微信文件类型](https://github.com/Tencent/openclaw-weixin/blob/main/src/api/types.ts)、[微信 CDN 上传](https://github.com/Tencent/openclaw-weixin/blob/main/src/cdn/upload.ts)、[微信媒体解密](https://github.com/Tencent/openclaw-weixin/blob/main/src/cdn/pic-decrypt.ts)、[QQ 预上传](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_users_user_id_upload_prepare.post.html)与[QQ 单聊发送](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_users_user_openid_messages.post.html)。

### 导出、备份恢复与容量管理（第六批）

点击工具栏的 **数据** 打开聊天数据管理面板。面板打开时保留聊天草稿与阅读位置，不因查看数据管理而推进已读。**导出、备份与恢复覆盖当前通道全部联系人及旧账号，不受“发送给”的选择影响**；容量总计覆盖整个 VsChat 存储目录，缓存隔离只处理当前通道。只有聊天分页、搜索和引用等会话操作按所选联系人隔离。

**导出聊天记录**可选择开始、结束日期，再导出为 Markdown 或 JSON；日期按界面所在时区解释，起止日期均包含当天，留空表示不限该端。分享导出保留正文和附件说明，剥离登录字段、附件下载 URL 与解密字段；它与用于恢复的 JSON 备份是两种格式，分享导出不能直接用于恢复。

**创建备份**保存当前微信或 QQ 通道的全部本地历史，可选择是否包含本地已缓存图片。日期筛选只作用于分享导出，不筛选备份。备份不会下载远程图片、文件或其他附件；缺失、损坏或无法收集的图片会在结果中报告。备份不包含账号登录凭据、会话令牌、当前路由或 QQ 回复配额，但可能包含附件签名 URL 与解密资料，应作为私有备份保存。

导出和备份单包最多 **10000 条消息、64 MiB**，恢复也使用这些上限；超限会报错，不会静默截断。分享导出可缩小日期范围，当前备份尚不支持分卷。保存时请选择扩展宿主中的新文件位置，已有文件不会被覆盖，也不能写入 VsChat 自身的数据目录。

恢复时先点击 **选择备份并预览**，查看消息与图片数量、日期范围，以及可追加、重复和冲突数量，再点击 **确认追加恢复**。只接受当前通道的备份；恢复只追加消息，重复及同标识内容冲突的条目会跳过，不覆盖或删除现有记录。原有未读进度、登录与路由状态、QQ 配额保持不变；导入历史不计入未读，也不触发新消息通知或激活新的发送路由。

当恢复记录位于聊天尾部时，已有未读采用保守策略，暂不因显示这些历史记录而自动清除；之后读到真实新消息，或另一窗口推进相应已读进度时再更新。

消息恢复与图片恢复分别报告结果。部分图片失败不会撤销已追加的消息，可以重新选择同一备份、预览并确认，重试补齐缺失图片；重复消息不会再次追加，已有缓存不会被覆盖。如果提示记录已保存但界面刷新尚未完成，数据已经提交，无需因此重复导入。恢复与缓存整理预览的有效期为 **10 分钟**，关闭数据面板、销毁或替换视图、清空历史后需重新预览，异步晚返回不会重新激活旧预览。关闭面板不会中断已经明确确认并提交的操作。

**查看 / 刷新容量**按类别显示当前通道数据库及其 `.bak`、图片缓存、文件草稿、临时文件、保留目录和其他文件的大小，并显示总量与文件数；总量包含扩展存储目录中的共享及其他文件。

**预览可整理缓存**只列出当前通道中超过 7 天、没有历史消息引用且符合插件命名规则的普通图片缓存。点击 **确认移入保留目录** 后会重新检查引用和文件变化；仍满足条件的文件移入存储目录下的 `cache-quarantine/`，变化项跳过，失败项单独报告。**这是保留文件的移动操作，不是删除，不会释放磁盘空间。** 它不处理聊天记录、凭据、草稿或未知文件，本批也没有删除保留目录内容的入口。

### 历史搜索与引用上下文

点击工具栏的 **搜索**，查询当前机器人账号与所选联系人的全部本地历史，不受聊天面板已加载条数限制；选择 **全部历史（只读）** 时才查询当前通道的跨联系人旧记录。关键词、起始日期、结束日期和消息类型可以组合使用；关键词留空时，可以只按日期或类型筛选，也可以浏览当前范围内的全部记录。类型包括文本、图片、语音、文件和视频。

关键词对已保存的消息正文做连续子串匹配，`%`、`_` 等符号按普通文字处理，英文字母（ASCII）不区分大小写。不支持正则表达式、分词或语义搜索，也不识别图片中的文字。日期按 Webview 的本地时区解释，起止日期均包含当天；结束日期实际匹配到次日零点之前。

结果按本地记录从新到旧排列，每页最多 50 条，可继续加载更早结果。点击一条结果，在独立的搜索区域查看该消息及前后各最多 10 条记录（合计最多 21 条），保留实时聊天列表和草稿；这不是将整段历史加载到聊天时间线。查看搜索结果或上下文不会提交已读进度。

点击聊天中的引用时，已加载的目标仍在聊天列表中定位；目标尚未加载则尝试从同一会话读取上下文，不能借引用跳到另一人的记录。目标不存在或历史已清空时会显示提示。切换联系人或任一共享窗口清空历史后，当前搜索结果及上下文会失效，需要重新搜索。

### 长历史与媒体开销（第八批）

数据库增加会话排序、真实入站未读、消息／引用定位及 QQ 回复窗口索引。联系人未读改为分组查询，QQ 联系人列表与可用回复额度在同一数据库快照中批量汇总，避免按联系人反复读取整个库。数据库仍使用 sql.js，每次操作在跨进程锁内重新读取整文件，写入时原子替换整文件；没有为提速复用可能过期的长期数据库内存快照。

普通“加载更早消息”通过 `DocumentFragment` 在列表顶部插入新节点，保留已有消息 DOM 和阅读锚点；需要替换已有内容或重置视图时仍会重绘。图片设置 `loading="lazy"` 和 `decoding="async"`。宿主每次准备历史页时最多并发读取 4 项媒体；图片展示缓存使用 LRU，最多 128 项、按字符串长度估算 16 MiB，并在历史 `generation` 或 `contentVersion` 变化时失效。Markdown 解析结果最多缓存 256 项、累计 256 × 1024 个源字符。

这些预算只限制**缓存保留量**，不是扩展或 Webview 的总内存上限。历史准备结果、传给 Webview 的载荷和已加载 DOM 仍会随加载量增长。本批没有生成缩略图、按需加载原图或实现虚拟列表，也没有新增 QQ 接收图片或已发送文件的本地缓存。

隔离基准使用 100000 条模拟消息、每账号 100 个联系人、63,688,704 字节数据库：在同一个已加索引的库中，旧联系人调用方式每轮读取数据库 102 次，中位耗时 589.532 ms；批量摘要读取 1 次，中位 78.717 ms（3 轮，本机样本约 7.49 倍）。这是调用方式的对照，不是旧版本到本批整体提速的保证。可复现：

```bash
node tests/history-performance-benchmark.cjs --rows=100000 --contacts=100
```

隔离 Chromium 检查中，初始 2000 条再前插 100 条，原 2000 个消息节点全部保留，12 项检查通过；一次环境样本的初始渲染、前插、重复页处理耗时分别为 60.8、15.1、1.3 ms，不能作为所有设备的耗时阈值。更大的历史、图片密集场景和 Remote SSH 仍需人工验收。

### 未读提醒与打开聊天

联系人列表分别显示未读数量，状态栏汇总当前机器人账号的未读数。未读只统计真实收到的消息，不统计自己发出的消息或导入历史；首次升级沿用已有已读基线。

只有当前 VS Code 窗口获得焦点、联系人聊天面板可见且已滚动到最新消息时，才会推进该会话的已读进度。其他联系人保持各自未读，共享窗口会同步同一会话的已读进度。查看较早历史、搜索、全部只读历史、隐藏面板或切换到其他窗口都不会把其他人的新消息自动标为已读。

点击状态栏，或执行 **VsChat: Open Chat**，会打开面板；已有选择时定位该会话最新消息，没有选择时需先选择联系人。新的未读消息到达时，只有获得焦点且聊天面板隐藏的窗口显示 VS Code 通知；点击通知里的 **打开聊天** 会打开对应联系人。打开历史或更新已读进度不会重放旧通知。

### 诊断日志

出现连接、收发消息或媒体上传问题时，执行 **VsChat: Show Diagnostic Logs**。日志包含本次扩展运行标识、通道、请求编号、HTTP 状态、QQ 业务错误码与 Trace ID、请求耗时、Gateway 状态、重连/重试次数和消息类型等信息。

日志不会记录 AppSecret、Access Token、微信会话 Token、AES 密钥或消息正文；AppID、OpenID、消息 ID、Session ID 和 Trace ID 会脱敏显示。向开发者反馈问题时，建议从扩展启动位置开始复制完整日志，以便通过请求编号串联故障链路。

QQ 发送日志另含 `replyContextKey`（入站消息 ID 的 SHA-256 摘要前 16 位）和 `replySequence`，可跨窗口核对同一个回复上下文是否重复使用序号，避免不同消息 ID 的脱敏首尾相同造成误判。接收日志通过 `eventKey`、`dbId` 和 `latestAdvanced` 区分重复事件、实际落库及会话是否前进，不记录消息正文。
