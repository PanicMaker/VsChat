# VsChat 功能建议清单

> 更新于 2026-11-12，依据 0.9.5 源码审查及本轮工作区实现整理。本轮改动尚未发布。

## 已有能力

- 微信 iLink / QQ Bot 双通道，通道历史分别存储；支持文本、图片收发、语音转写展示和引用回复。
- 历史分页、粘贴图片预览、发送图片回显及大图查看。
- 共享数据库的跨进程锁与原子保存；QQ 被动回复序号、入站去重和最近会话更新已经跨窗口协调。
- 本地历史支持引用预览及已加载消息跳转。微信客户端是否展示 bot 发出的引用受平台能力限制。

## 本轮已实现

- **发送状态与恢复**：显示发送中、已发送、发送失败或结果待确认；确认成功后清除对应草稿，失败或结果不明时保留内容，支持用户手动重试。请求 ID 防止同一扩展宿主内重复提交同一次发送；未知结果不会自动重发。
- **多行输入与草稿**：默认 Enter 发送、Shift+Enter 换行，兼容输入法组合输入；文字、引用、图片、文件草稿及发送回执保存在 Webview 状态中，按通道、机器人账号与联系人隔离，可在面板恢复后继续处理。
- **阅读位置与面板提示**：查看历史时保留阅读位置，接近底部才跟随新消息；面板显示新消息数量并提供回到最新入口。
- **多窗口历史同步**：启动后独立于面板运行；本地收发触发刷新，约每 1.5 秒检查共享数据库文件变化，仅变化或主动补同步时读取数据库。普通新增消息增量追加，清空操作通过数据代次重置视图；窗口聚焦和面板重新显示时补同步。
- **共享未读与通知直达**：按机器人账号与联系人维护独立已读进度，只统计真实收到的消息，导入历史不计未读；首次升级沿用已有已读基线。当前窗口有焦点、联系人面板可见并读到最新时只推进该会话已读，其他共享窗口随后同步。状态栏汇总当前账号未读，通知可打开对应联系人；仅有焦点且面板隐藏的窗口显示新消息通知。
- **发送快捷键设置**：`vschat.sendShortcut` 支持 `enter`（默认）或 `ctrlEnter`；后者用 Ctrl+Enter / Cmd+Enter 发送、Enter 换行。设置实时生效并更新输入提示，保留草稿；Shift/Alt+Enter 和输入法组合输入均不发送，默认模式下 Ctrl/Cmd+Enter 也不发送。
- **历史搜索与上下文定位**：工具栏搜索覆盖当前机器人账号与所选联系人的全部本地历史，支持正文连续子串、日期和类型组合筛选；空关键词可用于筛选或浏览。结果每页最多 50 条，按本地记录从新到旧排列。点击结果或尚未加载的引用，在同一会话内读取目标及前后各最多 10 条记录，不替换实时聊天列表、不提交已读；切换联系人或清空历史会使结果失效。“全部历史（只读）”另提供当前通道跨联系人旧记录的查看与搜索。

### 第四批：Markdown 与多附件接收

- **Markdown 与代码复制**：`vschat.renderMarkdown` 默认 `true`，在 Chat 和独立消息上下文显示 Markdown，并为代码块提供“复制代码”；设置热更新，关闭后显示原文。Output / Changes 中的消息文字保持纯文本。原始 HTML 仅显示文字，Markdown 内嵌图片不加载，外部链接受协议限制；过长或解析失败的内容回退为纯文本。
- **有序多内容消息**：保存同一条消息中的文字和全部附件项，保留协议提供的类型、名称、大小、链接等元数据；混合消息可按任一内容项类型搜索。微信按完整消息去重并原子更新会话信息，避免同一消息的后续内容项被去重丢弃。
- **微信逐项图片缓存**：正文与附件元数据先入库，图片分别下载、解密和缓存；单项失败不丢弃其他已保存内容。缓存完成会通知共享窗口重新加载。QQ 接收附件仍使用远程链接，本批没有增加 QQ 图片本地缓存。

第四批仅扩展接收、存储和显示。当时尚未提供的普通文件发送、文件解密下载与另存为，已在第五批补充。旧记录仍按已有数据兼容显示，无法恢复旧版本漏存的附件；多附件一起发送和编辑器打开流程尚未实现。

### 第五批：普通文件发送与另存为

- **原生选择与明确发送**：微信与 QQ 均可发送一个非空普通文件。点击“文件”打开原生选择对话框，宿主保存内容快照，Webview 仅持有草稿标识、名称与大小；选择不上传，需明确发送。文件与图片草稿互斥，文字和引用保留为独立草稿，不作为文件说明或引用一并发送。
- **发送状态与恢复**：上传准备失败可明确报告尚未发送；最终消息请求结果不明或缺少平台消息 ID 时保持“待确认”，不自动重发。确认成功后清除对应文件草稿；面板恢复会校验宿主中的草稿标识，宿主重启后需重新选文件，不提供断点续传。
- **附件另存为**：文件卡片按能力显示“另存为”或不可用原因，主聊天与消息上下文均可操作。原生对话框选择位置后，完成下载与校验再写入；提供保存中、成功、失败和取消状态，失败可手动重试。取消选择／保存对话框不会发消息或写入目标文件；下载中可请求“取消保存”，以最终结果为准，已开始的目标文件写入不能撤销。发送前可移除文件草稿，保存后不自动打开或执行文件。
- **通道差异与旧数据**：微信收到及确认发出的文件使用已存媒体引用与 AES 密钥下载、解密，协议提供大小或 MD5 时校验；旧 JSON 已存完整描述时可兼容读取，缺少密钥时显示不可用。QQ 收到的有效文件链接可另存为；QQ 发出的文件因上传响应没有下载 URL、且本批没有发送文件缓存，暂不能另存为。[QQ 上传响应](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_users_user_openid_files.post.html)
- **下载边界**：仅允许 HTTPS 的腾讯域名家族（`qq.com`、`qq.com.cn`、`qpic.cn`、`gtimg.cn` 及子域名），逐跳校验重定向，下载总超时 30 秒；按实际读取字节和解密后的大小限制。发送／下载上限均为 **20 MiB，这是本插件的应用限制，不是平台上限**。文件 URL 与解密信息只供宿主使用，不进入 Webview，CDN 下载不携带聊天凭据。

第五批未包含多文件一起发送、视频下载、自动打开文件、文件缓存管理与跨重启续传。第六批另补已缓存图片的备份恢复与无引用图片的保留目录整理，仍未增加 QQ 图片自动缓存，也无法补回此前已经漏存的附件。

协议参考：[微信文件类型](https://github.com/Tencent/openclaw-weixin/blob/main/src/api/types.ts)、[微信 CDN 上传](https://github.com/Tencent/openclaw-weixin/blob/main/src/cdn/upload.ts)、[微信媒体解密](https://github.com/Tencent/openclaw-weixin/blob/main/src/cdn/pic-decrypt.ts)、[QQ 文件预上传](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_users_user_id_upload_prepare.post.html)及[QQ 消息发送](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_users_user_openid_messages.post.html)。

### 第六批：导出、备份恢复与容量管理

- **分享导出**：工具栏“数据”面板可按开始、结束日期导出 Markdown 或 JSON。日期按界面时区解释，结束日期包含当天；导出正文及附件说明，剥离登录字段、附件下载 URL 与解密字段。分享导出格式不能作为恢复备份使用。数据管理始终覆盖当前通道全部联系人及旧账号，不受聊天收件人选择影响。
- **当前通道备份**：JSON 备份包含当前微信或 QQ 通道的全部本地消息，可选择包含本地已缓存图片；不下载远端图片、文件或其他附件，缺失／跳过图片单独报告。备份不包含账号登录凭据、会话令牌、路由状态或 QQ 配额，但可能包含附件签名 URL 与解密资料，属于私有数据。日期筛选仅用于分享导出。
- **预览后追加恢复**：先选择当前通道备份，查看消息、图片、日期范围及新增／重复／冲突数量，再明确确认。稳定归档标识支持重复恢复去重；同标识内容冲突的条目跳过，不覆盖或删除现有消息。恢复保留原有未读、路由与配额，导入历史不计入未读、不触发新消息通知，也不激活新的发送路由。导入记录位于聊天尾部时，已有未读暂不自动清除，之后读到真实新消息或另一窗口推进相应已读进度时再更新。
- **图片恢复与重试**：按恢复后的消息 ID 放置图片，已有缓存不覆盖；部分图片失败单独报告，不撤销已提交的消息。可重新选择同一备份、预览并确认，重试补齐缺失图片，消息不会重复追加。若仅提示已保存但界面刷新尚未完成（`refreshPending`），无需重复导入。
- **操作边界**：单包最多 10000 条消息、64 MiB，超限报错而不截断；目前没有分卷备份。导出／备份写入数据目录之外的新文件，不覆盖已有文件。恢复与整理预览有效 10 分钟，关闭数据面板或清空历史后需重新预览；关闭面板不会中断已明确确认并提交的操作。
- **容量与缓存整理**：分类显示当前通道数据库及 `.bak`、图片缓存、文件草稿、临时文件、保留目录、其他文件与总量。仅将超过 7 天、无历史引用且命名符合规则的普通图片缓存列入整理预览，明确确认后再次核验，再移入 `cache-quarantine/` 保留目录。变化项跳过、失败项报告，不处理聊天、凭据或草稿；**不删除文件、不释放磁盘空间**，本批无永久清理入口。

### 第七批：明确收件人与多联系人

- **显式选择与账号隔离**：聊天前在“发送给”中选择对象，以当前机器人账号与联系人共同标识会话。新来信不会自动选中或改变发送对象；各窗口保持自己的选择。按联系人 ID 展示本地已有私聊、当前账号只读历史及 QQ 配置候选，不提供全好友查询、好友昵称目录或群聊。
- **独立历史与未读**：聊天、增量同步、分页、搜索、消息上下文、引用定位和已读进度按会话隔离；读完甲不会清除乙的未读。状态栏汇总当前机器人账号未读，通知打开对应联系人。切换后的迟到响应不会混入当前列表。
- **独立草稿与回执**：文字、引用、图片、文件草稿及发送回执分别归属原联系人；宿主文件快照也绑定该对象。切换后迟到的文件选择或发送结果不会替换另一人的草稿。旧版未绑定草稿保留在“全部历史（只读）”供查看和手动复制，不自动绑定联系人或重试；文件需重新选择。
- **目标固定与会话校验**：提交发送时固定账号与联系人，上传及重试不改投；切换登录或凭据后中止失效的发送准备。QQ 令牌缓存与 Gateway 恢复校验凭据身份，旧连接来信仍归属原机器人账号。引用只能使用所选会话内经宿主核实的记录。
- **QQ 发送范围**：界面仅允许使用当前可用的被动回复额度；`vschat.qqUserOpenId` 只增加候选，不覆盖选择、不激活额度，也不保证主动发送权限。插件沿用 60 分钟／每条入站消息 4 次的计数，所有窗口共用；耗尽或过期不回退为主动发送。官方文档概要与 `msg_id` 字段对有效期的描述不一致，实际接口拒绝仍可能发生。[QQ 单聊发送](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_users_user_openid_messages.post.html)
- **微信发送范围**：本次登录的真实入站消息确认账号、联系人及各自会话信息，同一有效登录恢复可复用其绑定记录；历史导入和旧 `vschat.fromUserId` 配置不建立当前发送路由。轮询游标只用于继续接收，不能作为发送 `context_token`。`-14` 按登录失效处理并要求重新登录，不再去掉 token 重试。
- **只读历史与数据管理**：“全部历史（只读）”保留当前通道全部联系人及旧账号记录，可查看与搜索，但不能发送或推进已读。导入记录不激活发送能力。导出、备份、恢复与清空历史仍覆盖当前通道全部联系人；容量总计覆盖整个插件存储目录，缓存隔离仅处理当前通道，界面明确标示这一范围。

### 第八批：连接健康、长历史性能与 CI

- **独立连接状态**：增加离线、连接中、在线、恢复中和错误状态；QQ 显示最近心跳 ACK，微信显示最近成功轮询响应，退避时提供预计重试时间。状态栏独立于联系人、草稿、发送结果与未读，不因连接状态更新而切换联系人或推进已读。
- **QQ Gateway 恢复**：检测心跳 ACK 超时，控制帧不进入普通事件处理队列。事件串行处理，最多保留 256 个事件、8 MiB 队列载荷，单载荷上限 1 MiB；连接准备和事件处理均有 30 秒超时。业务处理成功后，将 Session、序列号和凭据身份作为一个检查点原子保存，恢复不越过未处理事件。积压、处理失败或超时从已保存位置恢复；临时断线退避重连，明确的不可恢复关闭码显示错误并停止循环。旧连接响应不能改变新连接状态。已进入数据库原子写入的操作不能强杀，重连会等待它结束；若底层存储永久卡住，需要排查并重载窗口。
- **微信轮询恢复**：停止、重启之间串行交接，旧轮次结束后才启动新轮询；轮询请求超时 45 秒，入站媒体超时 30 秒，请求、退避与媒体处理可取消。整批消息保存成功后才提交游标，存储或临时网络失败重试旧位置并去重；`-14`、HTTP 401 要求重新登录。游标按登录凭据隔离；首次升级不信任旧全局游标，从空游标重新请求服务端仍可返回的消息并去重，不保证补回服务端已不保留的历史。
- **数据库查询与联系人摘要**：增加会话排序、真实入站未读、消息／引用定位及 QQ 回复窗口索引；联系人未读用分组查询，QQ 联系人和可用回复额度从同一磁盘快照批量汇总。仍在跨进程锁内用 sql.js 每操作读取整个库，写入时原子替换整个库，不引入长期旧快照缓存。
- **历史页与展示缓存**：普通旧页用 `DocumentFragment` 前插，保留已有消息 DOM 与阅读锚点；图片使用 lazy loading 和 async decoding。每次历史准备最多并发读取 4 项媒体；图片展示 LRU 最多 128 项、按字符串估算 16 MiB，随 `generation/contentVersion` 变化失效；Markdown 解析缓存最多 256 项、256 × 1024 个源字符。预算只限制缓存保留量，历史准备结果、Webview 载荷和已加载 DOM 仍随加载量增长；本批没有缩略图、按需原图或虚拟列表。
- **CI 回归门槛**：[构建工作流](../.github/workflows/build.yml) 顺序执行 `npm ci` → `npm test` → 构建 → VSIX 打包，发布任务保留 `needs: build`。原发布分支和事件条件未改；本轮只做本地验证，没有触发托管 GitHub Actions、真实发布或真实聊天消息。

### 当前共同边界

“已发送”表示客户端调用成功，不代表收件人已阅读或保证对方收到；微信返回送达警告或发送过程异常时保守显示结果待确认。草稿虽按联系人隔离，恢复仍依赖 VS Code Webview 状态，并非数据库持久化发件箱，也没有跨窗口草稿同步。文件内容快照只在当前宿主中有效；完整重启后无法确认的旧发送需由用户核实，手动重发可能产生重复消息。

历史及未读同步仅适用于共用同一存储目录、同一通道数据库的窗口，所有共享写入者均需升级并重载；不协调不同机器、不同 VS Code 配置文件或其他独立数据库。清空历史会保留共享图片目录中的文件；第六批可将符合条件的无引用旧图片移入保留目录，但不会回收磁盘空间。

搜索匹配已存正文，`%`、`_` 按字面处理，ASCII 字母不区分大小写；不包含图片 OCR、分词、语义或正则搜索。日期按 Webview 本地时区取当天范围，结束日期包含当天。上下文最多 21 条，不提供从该位置无限展开历史的能力。

### 第八批性能证据

使用隔离临时数据生成 100000 条消息、每账号 100 个联系人，数据库 63,688,704 字节。复现命令为 `node tests/history-performance-benchmark.cjs --rows=100000 --contacts=100`（默认 3 轮）。没有使用用户聊天数据或真实网络。

| 对照项目 | 旧调用／查询形式 | 本批形式 | 样本范围 |

| 联系人及回复额度汇总 | 102 次整库读取，中位 589.532 ms | 批量摘要 1 次整库读取，中位 78.717 ms，约 7.49 倍 | 在**同一新增索引数据库**中对照调用形式，3 轮本机样本，不是历史版本整体性能保证。 |
